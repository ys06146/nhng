## ML 실행 결과와 제한
- 현재 main의 `python ml/train.py`에 모든 새 CSV를 넣으면 `ValueError: 'right' is not in list`로 중단된다. features.py는 left/right를 추출하지만 train.py의 classes는 5개 종류만 선언함. ML 담당 수정 필요. ML/UI 파일은 이번 작업에서 변경하지 않았다.
- 진단용으로 완료·단일톤·비간섭의 5세션(163007,164218,211226,212758,224220)만 별도 복사하여 기존 train.py를 실행했다. 따라서 이는 선택된 부분집합 결과이며 전체 배포 성능이 아니다.
- 5세션에서 세션 제외 교차검증, 후보 구간 450개: idle 243, push 62, pull 80, other 65. wave 없음. 5종 정확도라고 부르지 않는다.
- softmax 정확도 72.4%; push recall 61%, pull recall 69%. idle+other 후보 308개 중 push/pull 예측 20.8%.
- random forest 정확도 78.4%; push recall 58%, pull recall 57%. idle+other 후보 중 push/pull 예측 23/308=7.5%.
- idle이 많아 전체 정확도만으로 추천할 수 없다. 후보 구간 분류와 안내 시행 검출률은 분모가 다르다. 후보 추출 자체의 미검출도 별도 검증할 것.
- 학습 출력의 cue_report 오작동률은 라벨 idle 전체(시행 간 복귀 포함)를 분모로 쓰므로 이 문서의 endpoint idle 통계와 다르다. 그 값을 정지 상태 오작동/분으로 재인용하지 않는다.

## 지연
- 완료 주 세션에서 동일 1.5초 cue 창 내 첫 정답 감지 100건의 cue→감지 중앙값 549ms, 범위 50–1491ms.

## 추천 통계 방법
1. 맞힘/오인식/미인식: 각각 횟수/시행 수와 Wilson 95% CI. 0/20도 진짜 성공확률 0의 증거는 아님(상한 16.1%).
2. 같은 녹음의 판정기 A/B: 동일 cue·평가 창·첫 이벤트 규칙을 적용해 정확 McNemar. 세션/기기 내 반복이 있으므로 현재 p값은 탐색용; 세션·기기 단위 군집 순열/부트스트랩을 우선하며 현 독립 군집 수 4개는 작음.
3. 거리·음악 효과: 같은 사람·기기에서 모든 조건을 반복하고 순서를 섞는다. 표본 충분 시 성공 여부를 종속변수로 한 로지스틱 혼합모형(거리, 소음, 상호작용; 참가자/기기/세션 군집). 프레임을 독립 표본으로 하는 t검정·카이제곱 금지. 현재는 거리와 기기가 얽혀 유의성 검정으로 거리 효과 주장 불가.
4. 오작동: 노출 시간과 횟수, Poisson exact CI. 여러 세션 비교는 시간 offset을 둔 Poisson 회귀; 과산포면 negative binomial. 조용함과 타이핑은 분리. 같은 조건 3–5분 권장. 0건/15초는 안정성 입증이 아님.
5. 지연: 성공 시행만의 cue 지연은 중앙값·IQR과 미인식률을 함께 보고. 실제 onset 지연은 동기 영상/추가 센서 표식 필요. 같은 녹음 A/B는 대응 비교; 반복 시행 의존성은 세션 단위로 처리.
6. 여러 설정을 같은 데이터에서 고르면 검정/평가가 낙관적. 개발/선정 세션과 최종 평가 세션을 분리. 다중 비교가 필요하면 Holm 보정.

## 미인식·오작동·간섭을 줄이는 다음 실험
- 최신 사이트 재로딩 후 같은 기기·35cm에서 단일톤 push/pull 먼저 반복. 최소 2개 독립 새 세션, 각 방향 20회. 거리 외 설정을 고정하고 시스템 볼륨도 기록.
- 주변 다른 Bat Ears 노트북은 톤/마이크를 끄거나 한 대씩 측정. 간섭 유무 A/B는 같은 기기·거리에서 순서 교차하여 반복. foreignTones 값·주변 가동 기기·음악 재생기기/볼륨을 메모. 감지 마스크/주파수 선택은 엔진 담당과 조정하고 새 주파수에서 재보정.
- 빠르고 명확한 본 동작 + 느린 복귀. 시행 사이 중립 자세. 화면/스피커와 손 방향을 일정하게. 실패 자체로 라벨을 지우지 말고, 실제 동작을 안 했거나 안내를 놓친 경우에만 사유를 적어 취소.
- vMin/aOn을 내리면 작은 움직임 감지는 늘지만 오작동도 늘 수 있음. 엔진 담당이 기기별 개발 세션으로 제한된 후보를 선택하고 별도 세션에서 맞힘률·오작동/분·지연을 함께 검증. 기존 6dB UI가 burst의 aOn=12를 직접 바꾸는지 확인 없이 문턱값 조정 효과를 주장하지 않음.
- 좌우 실험은 별도 결과로 둔다. n0c4 55cm 좌우 live는 0/12, 보정 LOO 8/12라도 push/pull을 swipe로 오인한 비율 4/10. 보정 성능을 실시간 게임 성능으로 표기하지 않음. 안정된 push/pull 데모 우선.
- 계획 거리 35/50/65cm를 유지할지 실제 사용한 35/55/65cm로 고칠지 먼저 기록을 확정. 55를 50으로 임의 변경하지 않음. 각 조건에 동일한 사람 식별자 p1/p2를 유지. 현재 부족한 조건·사람을 채워야 사람/소음별 표를 완성할 수 있음.

## 재현
`python experiments/audit_current.py --data /path/to/Drive/nhng/ml/data --ml ml --out experiments`

- scipy 설치 시 Poisson CI와 정확 McNemar p도 생성. 없으면 해당 계산은 생략, Wilson 계산은 표준 라이브러리.
- `session_stats.csv`는 전체 20세션의 상태·실시간·replay 집계. 생성되는 audit.json은 세션별 rate CI와 진단 세부값을 포함(로컬 산출물).
- main `ml/replay_burst.py`의 quiet 시간은 고정 60fps 분모를 사용함. 본 audit는 실제 타임스탬프의 연속 동일 조건 구간을 합산하며 250ms 초과 관찰 공백은 제외. 해당 세션의 공백 수를 CSV에 기록.
- report.py는 중단 세션을 cue 수로만 거르고, 메타데이터 없는 파일도 총계에 포함함. 본 문서의 명시적 완료 세션 분모와 달라 수치 차이가 발생함.
- 원본·ml 코드·UI·main은 수정하지 않음. 향후 실험 거리 계획: 35→50→65cm (사용자 변경 요청).
